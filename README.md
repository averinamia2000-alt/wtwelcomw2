# Whitech Helper — фикс трёх проблем

## 1. Обрывает ответы на середине ("недописывает")

`gpt-5-mini` — reasoning-модель. В Responses API токены на внутреннее
рассуждение списываются из того же бюджета `max_output_tokens`, что и
видимый ответ. При лимите 1200 модель могла тратить большую часть
бюджета на "размышление", и на сам текст оставалось несколько токенов —
отсюда обрыв ровно после пункта 1.

Исправлено:
- `max_output_tokens` поднят до 3000
- добавлен `reasoning={"effort": "minimal"}` — меньше токенов уходит на
  скрытые рассуждения, больше остаётся на текст
- если API всё же вернёт `status == "incomplete"`, это теперь логируется
  и попадает в аналитику (`incomplete_model_output`), чтобы дальше было
  видно, если проблема повторится

## 2. Просто не присылает ответ

Отправка финального сообщения (`status.edit_text` / `message.answer`)
не была обёрнута в try/except — только вызов `build_answer()`. Если
Telegram API отклонял именно отправку (устаревшее сообщение для edit,
"message not modified", сетевой сбой), исключение падало необработанным,
aiogram просто логировал ошибку — и пользователь не получал вообще
ничего, при том что ответ был успешно посчитан.

Исправлено: отправка обёрнута в try/except с fallback на обычный
`message.answer`, если `edit_text` не сработал.

## 3. Не находит ответ, который точно есть на странице

Самая существенная причина: `ancestor=ALLOWED_ROOT_PAGE_ID` — жёсткий
CQL-фильтр на одно-единственное поддерево страниц (было захардкожено
`3621748974`). Любая страница вне этого поддерева не участвовала в
поиске вообще, независимо от совпадения ключевых слов.

Исправлено:
- `ALLOWED_ROOT_PAGE_ID` → `ALLOWED_ROOT_PAGE_IDS` (через запятую,
  можно несколько корней). **Если переменная не задана — ограничения
  нет, поиск идёт по всему пространству `pmprod`.** Это меняет
  поведение по умолчанию — раньше искало только в одном поддереве,
  теперь везде, если явно не ограничить.
- окно текста страницы (`MAX_PAGE_CHARS`, было жёстко 9000) и окно
  скоринга в `rerank` были рассинхронизированы: скоринг смотрел только
  на первые 2500 символов, из-за чего страница могла найтись, но не
  попасть в топ-4, если совпадение было ближе к концу текста. Теперь
  скоринг смотрит на весь загруженный текст.
- добавлено логирование всех кандидатов с их score перед отсечкой
  топ-4 (`Candidates before cutoff: ...`) — если в следующий раз
  ответ не найдётся, в логах будет видно: страница вообще не попала
  в выдачу (проблема в CQL/ancestor) или попала, но получила низкий
  score (проблема в ранжировании).

## Что стоит сделать после обновления

- Если раньше `ALLOWED_ROOT_PAGE_ID` использовался осознанно (чтобы
  бот не лез в чужие/приватные ветки пространства) — задай
  `ALLOWED_ROOT_PAGE_IDS` явно со всеми нужными корневыми ID через
  запятую, иначе поиск станет неограниченным по всему pmprod.
- Убедись, что пакет `openai` обновлён (`pip install -U openai`) —
  параметр `reasoning` в Responses API поддерживается только в
  свежих версиях SDK.
